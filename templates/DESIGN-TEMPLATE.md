## 7. Do's and Don'ts

### Do

- Use `{{COLOR_SEMANTIC_BG_DEFAULT}}` as the page background — it anchors the visual identity
- Use `{{COLOR_INTERACTIVE_PRIMARY}}` only for primary CTAs and the highest-signal interactive elements
- Apply `{{RADIUS_BUTTON}}` radius to buttons and `{{RADIUS_CARD}}` radius to cards — radius defines the system's personality
- Reference CSS variables (`{{CSS_VAR_PREFIX}}-*`) in components — never hardcode colors or sizes
- Use background-color layering ({{BG_LAYERING_SEQUENCE}}) for depth before reaching for shadows
- Keep body line-height at `{{BODY_LINE_HEIGHT}}` or above for readability
- Follow the spacing scale — every margin/padding should map to a `space.*` token

### Don't

- Don't hardcode hex values in components — always reference a token or CSS variable
- Don't introduce colors outside the defined palette — extend `tokens.json` instead
- Don't hand-edit `src/styles/tokens.css` or the generated block in `tailwind.config.ts`
- Don't use font weights outside the defined scale ({{DEFINED_FONT_WEIGHTS}})
- Don't reduce body text below `{{FONT_SIZE_BODY_MIN}}` — minimum readable size
- Don't add box-shadows on every surface — {{SHADOW_RESTRAINT_RULE}}
- Don't deviate from the `{{SPACE_BASE}}px` grid — use spacing tokens only

### Iteration Guide

1. Always reference token names rather than hardcoded values: say "use `{{TOKEN_BG_DEFAULT}}`" not "make it white"
2. Specify the weight explicitly: "weight `{{HEADING_WEIGHT}}`" for headings, "weight `{{WEIGHT_REGULAR}}`" for body
3. Use the radius scale: "button uses `{{RADIUS_BUTTON}}`" — never say "rounded corners"
4. For hover states: "background shifts to `{{COLOR_INTERACTIVE_HOVER}}`" — one specific value
5. Depth: reach for background layering before shadows — "surface on `{{COLOR_BG_CARD}}`" before "add a shadow"
6. For spacing: "padding: `{{SPACE_4}}`" or reference the token, never a raw px value
7. Stay in-system: if a needed color/size doesn't exist in the token list, add it to `tokens.json` first, then use it
